# Crontab Formatter для VS Code

[English version](README.md)

Crontab Formatter — расширение VS Code для форматирования файлов cron и crontab в читаемые, выровненные колонки. Оно добавляет подсветку синтаксиса cron, неблокирующую диагностику, расшифровку расписаний и применяемые по выбору быстрые исправления. При обычном форматировании значения расписания и содержимое команды не переписываются.

Расширение предназначено для системных администраторов, разработчиков и всех, кто просматривает пользовательские crontab, `/etc/crontab` или файлы из `cron.d` в Visual Studio Code.

## Скачивание и установка

Готовый к установке выпуск — [Crontab Formatter v0.3.0](https://github.com/e-u-shapovalov/crontab-formatter/releases/tag/v0.3.0). Для него нужен Visual Studio Code 1.75.0 или новее.

Скачайте [`crontab-formatter-0.3.0.vsix`](https://github.com/e-u-shapovalov/crontab-formatter/releases/download/v0.3.0/crontab-formatter-0.3.0.vsix). Файл VSIX — это пакет расширения VS Code: устанавливайте его как файл и не распаковывайте.

Если вы раньше не пользовались GitHub:

1. Откройте страницу [Releases](https://github.com/e-u-shapovalov/crontab-formatter/releases).
2. Откройте самый новый выпуск. Подтверждённый актуальный выпуск — `v0.3.0`.

4. Скачайте файл с расширением `.vsix`. Не выбирайте **Source code (zip)** или **Source code (tar.gz)**.

Подтверждённый канал распространения версии 0.3.0 — GitHub Releases. Если поиск расширений VS Code не показывает Crontab Formatter, установите VSIX по инструкции выше.

## Быстрый старт

1. Откройте распознанный crontab-файл либо выберите режим языка **Crontab** или **Cron** в строке состояния VS Code.
2. Откройте Command Palette и выполните **Crontab: Форматировать документ** или стандартную команду VS Code **Format Document**.
3. Для автоматического форматирования включите Format on Save для идентификаторов языков `crontab` и `cron`:

```jsonc
"[crontab]": {
  "editor.defaultFormatter": "EvgeniiShapovalov.crontab-formatter",
  "editor.formatOnSave": true
},
"[cron]": {
  "editor.defaultFormatter": "EvgeniiShapovalov.crontab-formatter",
  "editor.formatOnSave": true
}
```

Расширение редактирует только текст в VS Code. Оно не устанавливает файл в системный crontab, не запускает задания cron и не заменяет службу cron.

## До и после

До форматирования:

```crontab
0 3 * * 1 /usr/bin/backup.sh
30 0 * * * /usr/bin/cleanup --verbose
*/15 * * * * /usr/bin/health-check
```

После форматирования:

```crontab
0     3  *  *  1  /usr/bin/backup.sh
30    0  *  *  *  /usr/bin/cleanup --verbose
*/15  *  *  *  *  /usr/bin/health-check
```

Форматтер меняет интервалы между колонками, но не переписывает значения расписания и не нормализует пробелы внутри тела команды.

## Чем это полезно

- Поддержка стандартных **Format Document**, **Format Selection** и **Format on Save** упрощает просмотр и ревью cron-расписаний.
- Пользовательские и системные crontab получают правильную раскладку, включая колонку `USER` в системном формате.
- При обычном форматировании команды остаются сырым текстом: кавычки, пайпы, перенаправления, `&&`, `||`, `%`, `$()`, бэктики, внутренний `#` и внутренние пробелы не разбираются на токены и не нормализуются.
- Комментарии, пустые строки, присваивания окружения и поддерживаемые `@макросы` обрабатываются отдельно и не принимаются за расписание.
- Диагностика указывает на подозрительные поля и перенаправления, но не блокирует форматирование и не имитирует выполнение расписания.
- При наведении поддерживаемое cron-выражение расшифровывается на русском или английском с помощью [`cronstrue`](https://github.com/bradymholt/cRonstrue).
- Встроенная TextMate-грамматика подсвечивает расписания, команды, переменные окружения, комментарии, shell-переменные и цели перенаправлений. Конкретные цвета зависят от активной темы VS Code.

## Возможности

### Форматирование

- Выравнивает пять стандартных полей: минуты, часы, день месяца, месяц и день недели.
- Выравнивает поле `USER` в системных crontab.
- Позволяет явно включить ведущее поле секунд, хвостовое поле года или оба поля.
- Выравнивает строки поддерживаемых макросов, например `@reboot`, `@daily` и `@hourly`.
- По желанию выравнивает `=` в присваиваниях окружения.
- По желанию выравнивает хвостовые перенаправления и безопасные хвостовые комментарии.
- По желанию вставляет строку-памятку с названиями колонок.
- Сохраняет окончания строк LF или CRLF и наличие финального перевода строки.
- Даёт стабильный результат: повторное форматирование уже выровненного типового файла не продолжает менять его.

### Диагностика и подсказки

Мягкая диагностика сообщает о следующих ситуациях:

- слишком мало полей или невалидный синтаксис расписания;
- значения за пределами поддерживаемого диапазона поля;
- нулевой шаг, например `*/0`;
- перевёрнутый диапазон, например `18-9`;
- неизвестный макрос;
- пустая команда;
- отсутствующий пользователь в системном режиме;
- отсутствующее, неполное или ошибочное перенаправление вывода.

Отсутствие перенаправления — эксплуатационная подсказка, а не синтаксическая ошибка cron. Диагностика носит информационный характер и не блокирует форматирование.

Расширение также предоставляет:

- русские или английские расшифровки при наведении и через команду **Crontab: Объяснить текущую строку**;
- команду **Crontab: Определить формат** с информацией о раскладке и количестве строк;
- шаблон автодополнения после ввода `*` в пустой строке;
- явные Code Actions для добавления `>/dev/null 2>&1`, перенаправления в `/var/log/...`, добавления `2>&1`, замены начального `php` на `/usr/bin/php`, расшифровки расписания и преобразования точного пятипольного расписания в равноценный поддерживаемый макрос.

Быстрые исправления выполняются только после выбора пользователем. Проверяйте предлагаемые пути и перенаправления: `/usr/bin/php` может отсутствовать на вашей системе, а для записи в `/var/log` могут потребоваться права.

## Поддерживаемые файлы и форматы cron

VS Code связывает расширение со следующими файлами:

- расширения `.crontab` и `.cron`;
- имена `crontab`, `crontab.tmp` и `cron`;
- пути по шаблонам `**/cron.d/*` и `**/etc/crontab`.

Если используется другое имя, вручную выберите режим языка **Crontab** или **Cron**.

Поддерживаемые типы строк:

- пользовательский crontab: `MIN HOUR DOM MON DOW COMMAND`;
- системный crontab и `cron.d`: `MIN HOUR DOM MON DOW USER COMMAND`;
- необязательные шести- или семипольные раскладки, когда настройки секунд/года включены явно;
- макросы `@reboot`, `@yearly`, `@annually`, `@monthly`, `@weekly`, `@daily`, `@midnight` и `@hourly`;
- присваивания окружения, например `PATH=...`, `MAILTO=...` и `CRON_TZ=...`;
- комментарии на всю строку и пустые строки.

Поля cron принимают `*`, числовые значения, списки через запятую, диапазоны и числовые шаги. Распознаются английские трёхбуквенные названия месяцев и дней недели. Специфичные для других планировщиков токены вне этой грамматики, в том числе Quartz-операторы `?`, `L`, `W` и `#`, не считаются валидными полями расписания, поэтому строка остаётся неотформатированной.

## Команды

| Команда | Назначение |
| --- | --- |
| **Crontab: Форматировать документ** | Отформатировать активный cron-документ. |
| **Crontab: Объяснить текущую строку** | Показать понятную расшифровку текущего расписания. |
| **Crontab: Определить формат** | Показать user/system-режим, флаги секунд/года, количество строк и строки с диагностикой. |

Расширение также реализует стандартное действие VS Code **Format Selection**. Ширина колонок рассчитывается по всему документу, чтобы выделенные строки оставались выровнены с остальным файлом.

## Настройки

Откройте панель Extensions, нажмите шестерёнку рядом с Crontab Formatter и выберите **Extension Settings**.

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `crontabFormatter.mode` | `auto` | Выбрать `user`, `system` или определение по имени и содержимому файла. |
| `crontabFormatter.secondsField` | `auto` | Считать ведущее поле секундами. Сейчас `auto` работает как выключено. |
| `crontabFormatter.yearField` | `auto` | Считать последнее поле расписания годом. Сейчас `auto` работает как выключено. |
| `crontabFormatter.alignComments` | `false` | Выравнивать хвостовой `#`-комментарий, найденный вне кавычек. |
| `crontabFormatter.alignRedirects` | `false` | Выравнивать первое перенаправление `>` вне кавычек и его хвост. |
| `crontabFormatter.alignEnvEquals` | `false` | Выравнивать `=` в присваиваниях окружения. |
| `crontabFormatter.insertHeader` | `false` | Вставлять памятку `# min hour day month weekday command`. |
| `crontabFormatter.preserveIndentation` | `false` | Сохранять начальные отступы вместо выравнивания от левого края. |
| `crontabFormatter.minSpacesBetweenColumns` | `2` | Задать минимум пробелов между колонками; минимальное значение — `1`. |
| `crontabFormatter.formatMacros` | `true` | Выравнивать поддерживаемые строки `@макросов`. |
| `crontabFormatter.validateOnSave` | `true` | Включить мягкую диагностику при редактировании, открытии и сохранении файла. |
| `crontabFormatter.explainHover` | `true` | Показывать понятную расшифровку расписания при наведении. |
| `crontabFormatter.locale` | `ru` | Использовать `ru`, `en` или `auto` для сообщений и расшифровок расширения. |

Описания параметров следуют языку интерфейса VS Code. Параметр `crontabFormatter.locale` управляет диагностикой, сообщениями и расшифровками самого расширения; текущее значение по умолчанию — русский язык.

## Памятка по перенаправлениям

- `>` перезаписывает файл.
- `>>` дописывает данные в конец файла.
- `2>&1` отправляет стандартный поток ошибок туда же, куда стандартный вывод.
- `command >/dev/null 2>&1` отбрасывает оба потока вывода.
- `command >>/var/log/job.log 2>&1` дописывает оба потока в лог, если у пользователя cron есть право записи.

Эти примеры объясняют подсказки расширения по перенаправлениям и не применяются автоматически.

## Ограничения и безопасность

- Это расширение VS Code, а не отдельный консольный форматтер, настольное приложение, демон cron или установщик crontab.
- Форматирование не доказывает, что задание запустится. На выполнение по-прежнему влияют окружение, права, пути к программам, поведение shell, часовой пояс и конкретная реализация cron.
- Автоматическое определение user/system основано на эвристике. Для неоднозначных файлов, особенно одной системной строки с необычным именем файла, может потребоваться явный `crontabFormatter.mode`.
- Значения `secondsField: auto` и `yearField: auto` намеренно работают как выключено. Включайте нужное поле явно.
- Расширенные диалекты планировщиков поддерживаются не полностью. В частности, включение секунд/года не добавляет все операторы Quartz.
- При текстовой расшифровке расписания поле года отбрасывается.
- Невалидные и неполные строки расписания сохраняются вместо принудительного форматирования.
- В опубликованном VSIX `v0.3.0` параметры `alignRedirects` и `alignComments` по умолчанию выключены. Их разборщик учитывает одинарные и двойные кавычки и бэктики, но не моделирует вложенный shell-синтаксис вроде `$()`; при включении этих параметров для сложных команд проверяйте diff.
- `insertHeader` добавляет новую строку-комментарий. При включённом параметре форматирование выделения может затронуть весь документ из-за изменения количества строк.
- Диагностика — ограниченный набор подсказок, а не полный валидатор crontab. Версия 0.3.0 не проверяет, абсолютны ли пути команд.
- В опубликованном VSIX `v0.3.0` названия Code Actions «объяснить расписание» и «преобразовать в макрос» остаются русскими даже при English locale. На их работу это не влияет.
- Подсветка синтаксиса рассчитана на стандартную пятипольную раскладку; в вариантах с секундами/годом отдельные токены могут получить не те области подсветки.

Перед установкой crontab в рабочую систему всегда просматривайте diff после форматирования.

## Решение проблем

### VS Code сообщает, что скачанный файл не является допустимым расширением

Убедитесь, что имя заканчивается на `.vsix` и файл скачан из списка **Assets** нужного выпуска. GitHub-архив **Source code** не является VSIX-пакетом. Скачайте asset заново и установите его через **Install from VSIX…**. Также проверьте, что версия VS Code не ниже 1.75.0.

### Команды Crontab не появляются

Проверьте индикатор языка в правом нижнем углу VS Code. Выберите **Crontab** или **Cron**, затем снова откройте Command Palette. Если расширение только что установлено, один раз перезагрузите окно VS Code.

### Format Document ничего не меняет

Строка может быть неполной или использовать неподдерживаемый синтаксис полей — в таком случае она намеренно сохраняется. Проверьте панель Problems и `crontabFormatter.mode`; если в файле больше пяти временных полей, явно настройте секунды/год.

### Системный crontab выравнивается как пользовательский

Установите `crontabFormatter.mode` в `system`. Автоопределение смотрит на имя и содержимое файла и может ошибаться на коротких или неоднозначных файлах.

### Не срабатывает Format on Save

Назначьте Crontab Formatter параметром `editor.defaultFormatter` для активного идентификатора языка и включите `editor.formatOnSave`. Если в рабочей области есть файлы обоих типов, добавьте блоки `[crontab]` и `[cron]`, как показано в [быстром старте](#быстрый-старт).

### Слишком много подсказок о перенаправлении

Это информационные рекомендации. Отключите `crontabFormatter.validateOnSave`, если диагностика не нужна, либо оставьте её и игнорируйте подсказки, не относящиеся к вашему окружению cron.

### Некоторые быстрые действия названы по-русски

Это известное ограничение локализации опубликованного VSIX версии 0.3.0 для двух Code Actions. Остальные сообщения расширения следуют `crontabFormatter.locale`.

## Частые вопросы

### Что скачивать обычному пользователю?

Скачайте `crontab-formatter-0.3.0.vsix` из [GitHub Releases](https://github.com/e-u-shapovalov/crontab-formatter/releases), затем выберите **Install from VSIX…** в VS Code.

### Почему не нужно использовать Code → Download ZIP?

Эта кнопка скачивает исходные файлы репозитория. Для обычной установки VS Code ожидает упакованный asset с расширением `.vsix`.

### Форматирование меняет время запуска задания?

Обычное форматирование не переписывает значения расписания, а только выравнивает текстовые колонки. Явные быстрые исправления и включаемые параметры вроде вставки заголовка выполняют изменения, указанные в их названиях, поэтому перед применением crontab проверяйте diff.

### Расширение устанавливает или запускает задания cron?

Нет. Оно редактирует текст cron внутри VS Code. Для установки, просмотра, проверки и запуска заданий используйте средства вашей операционной системы.

### Есть ли отдельный CLI?

Проект не определяет отдельный CLI. Команда `code --install-extension` устанавливает расширение в VS Code, но не форматирует crontab из терминала.

### Поддерживаются ли шести- и семипольные cron-выражения?

Форматтер умеет добавлять ведущее поле секунд и хвостовое поле года, если включить их явно. Автоматическое определение обоих полей сейчас работает как выключено, а специальные операторы Quartz не поддерживаются.

### Какие языки интерфейса доступны?

Расширение предоставляет русские и английские сообщения и расшифровки. Параметры пакета и названия команд локализуются по языку интерфейса VS Code с учётом отмеченного выше ограничения двух Code Actions в опубликованной версии 0.3.0.

## Сборка из исходников

Сборка нужна контрибьюторам и пользователям, которые намеренно хотят изучить исходники. Для обычной установки используйте готовый VSIX.

Требования:

- Git;
- Node.js и npm; проект не объявляет точную минимальную версию Node.js;
- Visual Studio Code 1.75.0 или новее для запуска расширения.

Клонирование, установка зависимостей, компиляция и тесты:

```shell
git clone https://github.com/e-u-shapovalov/crontab-formatter.git
cd crontab-formatter
npm ci
npm run compile
npm test
```

Создание VSIX и установка собранной версии:

```shell
npm run package
code --install-extension crontab-formatter-0.3.0.vsix
```

Скрипт упаковки вызывает `npx vsce package --ignoreFile .vsce-pack-ignore`; если упаковщик ещё не находится в кэше, `npx` может понадобиться доступ к сети для его получения. В репозитории нет отслеживаемой конфигурации запуска VS Code Extension Development Host.

Доступные npm-скрипты:

| Скрипт | Действие |
| --- | --- |
| `npm run compile` | Скомпилировать TypeScript в `out/`. |
| `npm run watch` | Перекомпилировать TypeScript при изменении исходников. |
| `npm test` | Скомпилировать проект и запустить тесты Node.js из `out/test/`. |
| `npm run package` | Собрать пакет `.vsix` с помощью `vsce`. |

Точка входа расширения — `out/src/extension.js`, собранный из `src/extension.ts`. Парсер, форматтер, валидатор и расшифровщик отделены от интеграции с VS Code, поэтому их можно тестировать модульно. Зависимость времени выполнения — `cronstrue`; TypeScript и пакеты типов Node.js/VS Code используются для разработки.
